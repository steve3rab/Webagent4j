# Architecture decision records

ADRs preserve architectural rationale. They are historical decision records, not a substitute for current Javadoc/domain contracts. If an ADR and a current normative guide differ because the implementation evolved, the current guide wins and the ADR should be marked superseded/amended rather than silently rewritten as if history never happened.

Every ADR should state Status, Context, Decision, Consequences, and—when applicable—Supersedes/Superseded by.
